# Proposing a change to the trip

The itinerary is a file in this repository:
[`public/trips/sydney-2026.json`](public/trips/sydney-2026.json).

The published site is built from whatever that file says. Your own edits stay on
your device until you propose them, and a proposal only becomes part of the plan
once the owner accepts it. Nothing you do in the app can change what other
people see.

## From the app (no Git needed)

1. Open the app and edit the trip however you like — move an activity to another
   day, add an idea, fix a time.
2. Go to **Settings → Shared plan → Propose changes**. This saves
   `sydney-2026.json` to your device.
3. Click **open GitHub** in the message that appears. GitHub will make you a
   copy of the project automatically (a "fork") — you do not need permission for
   this.
4. Drag the file you just saved into the upload page.
5. Choose **"Create a new branch for this commit and start a pull request"**,
   write a line about what you changed, and submit.

That's it. The owner gets your proposal, can see exactly which lines changed,
and merges it if they agree. A few minutes after they merge, the site rebuilds
and everyone's app offers to pick up the new version.

## What happens to your proposal

Every proposal runs the project's checks automatically before anyone reviews it:

| Check | What it catches |
| --- | --- |
| `npm test` | Broken JSON, an activity pointing at a day that doesn't exist, a booking reference that leads nowhere, coordinates off the planet |
| `npm run lint` / `typecheck` | Code changes that don't compile |
| `npm run build` | Anything that would break the deployed site |

A red check means the proposal would corrupt the plan. Fix it and push again to
the same branch — the pull request updates itself.

## Getting the latest plan

The app checks on startup, and **Settings → Shared plan → Check for updates**
asks on demand. If your device is behind, **Adopt published plan** replaces your
local copy with the published one.

Adopting is destructive: it overwrites anything you have not proposed yet.
Export first (**Settings → Data → Export JSON**) if you are unsure.

## For the owner

- Proposals arrive at <https://github.com/nic4wtf/atlas-trip-planner/pulls>.
- `main` is protected: changes land through a pull request, so nothing reaches
  the published plan without you merging it.
- Merging triggers the deploy. Watch it under **Actions**.
- To edit the plan yourself, just use the app on your own machine and commit —
  or edit the JSON directly.

## Changing the trip file by hand

The file is generated by [`scripts/build-sydney-trip.mjs`](scripts/build-sydney-trip.mjs),
which is the readable source for the whole itinerary:

```bash
npm run trip:build     # rewrites public/trips/sydney-2026.json
npm test               # verifies the result
```

Editing the JSON directly is fine too — the generator is a convenience, not a
gate. Just keep the ids stable so the diff stays readable.
